# API бэкенда

Три эндпоинта, к которым обращается приложение.

> [!WARNING]
> Пути запросов, метод обмена и имена полей восстановлены из сборки `MeterParser-v1_0_0.apk` — они точны. Структура тел ответов приведена в том виде, в каком её использует приложение; точные схемы и коды ошибок сверяйте с документацией самого бэкенда.

## Базовый адрес

Берётся из настроек приложения, по умолчанию:

```
https://meter.mosoblenergo.ru
```

Хранится на устройстве в AsyncStorage под ключом `@meter_parser_api_url`. Пути ниже дописываются к нему приложением — в настройках указывают только схему, хост и при необходимости порт.

Приложение принимает `http` и `https`, имя хоста или IP-адрес, порт от 1 до 65535.

## POST /api/upload

Выгрузка снимка на распознавание. Вызывается сразу после нажатия спуска.

Тело — `multipart/form-data`, файл передаётся под именем `photo.jpg`.

```http
POST /api/upload HTTP/1.1
Host: meter.mosoblenergo.ru
Content-Type: multipart/form-data; boundary=----MeterParserBoundary

------MeterParserBoundary
Content-Disposition: form-data; name="photo"; filename="photo.jpg"
Content-Type: image/jpeg

<двоичные данные снимка>
------MeterParserBoundary--
```

В ответе приложение ожидает распознанные значения и ссылку на сохранённый снимок:

```json
{
  "meterNumber": "1234567890",
  "reading": "001234",
  "tariff": "T1",
  "meterType": "Меркурий 230",
  "digitCount": 1,
  "imageUrl": "https://meter.mosoblenergo.ru/media/2026/09/21/a1b2c3.jpg"
}
```

Любое из полей может прийти пустым — приложение подставит что есть и оставит остальное обходчику. Ошибка на этом шаге показывается как <span class="ui">Не удалось распознать счётчик:</span> с текстом ответа.

## POST /api/confirm

Создание записи показания. Вызывается по кнопке <span class="ui">Отправить</span> после того, как обходчик проверил поля.

Тело — JSON с подтверждёнными значениями и ссылкой на ранее выгруженный снимок:

```json
{
  "meterNumber": "1234567890",
  "reading": "001234",
  "tariff": "T1",
  "meterType": "Меркурий 230",
  "digitCount": 1,
  "imageUrl": "https://meter.mosoblenergo.ru/media/2026/09/21/a1b2c3.jpg"
}
```

Приложение проверяет перед отправкой единственное условие: непустым должно быть хотя бы одно из полей `meterNumber` или `reading`. Остальные поля могут быть пустыми.

Успешный ответ приводит к экрану <span class="ui">Показание успешно сохранено!</span>, неуспешный — к <span class="ui">Ошибка сохранения</span>.

> [!ATTENTION]
> Приложение не передаёт ключ идемпотентности. Если ответ потерялся в сети, обходчик может отправить показание повторно и создать дубликат. При доработке бэкенда стоит предусмотреть отсечение повторов по паре «номер прибора + показание + сутки».

## GET /api/today

Список записей за текущий день. Вызывается при открытии экрана <span class="ui">Показания за сегодня</span> и не принимает параметров — ни даты, ни идентификатора устройства.

```http
GET /api/today HTTP/1.1
Host: meter.mosoblenergo.ru
```

В ответе — записи, каждая с теми же полями, что и при подтверждении:

```json
[
  {
    "meterNumber": "1234567890",
    "reading": "001234",
    "tariff": "T1",
    "meterType": "Меркурий 230",
    "digitCount": 1,
    "imageUrl": "https://meter.mosoblenergo.ru/media/2026/09/21/a1b2c3.jpg"
  }
]
```

Приложение показывает их карточками и фильтрует локально по подстроке номера прибора — серверного поиска нет. Сбой запроса показывается как <span class="ui">Не удалось загрузить данные</span>.

Поскольку параметров нет, «сегодня» определяет сервер по своим часам. Расхождение часовых поясов между сервером и телефоном сдвинет границы суток для всей смены.

## Поля

| Поле | Тип | Экран приложения | Смысл |
|---|---|---|---|
| `meterNumber` | строка | № прибора учёта | Заводской номер счётчика |
| `reading` | строка | Показание | Цифры с табло, с ведущими нулями, без разделителя |
| `tariff` | строка | Тарифность | `T1`, `T2` или `T3` |
| `meterType` | строка | Тип прибора | Модель, например `Меркурий 230` |
| `digitCount` | число | Разрядность | Знаков после запятой: `0`, `1` или `2` |
| `imageUrl` | строка | Ссылка на фото | Адрес сохранённого снимка |

`reading` передаётся строкой, а не числом, — это существенно: ведущие нули несут информацию о разрядности табло и при приведении к числу теряются. Позиция запятой определяется полем `digitCount` уже на стороне учётной системы.

## Проверка связи

При сохранении адреса на экране настроек приложение обращается к серверу и по результату показывает один из ответов:

| Результат обращения | Сообщение |
|---|---|
| Сервер ответил успешно | <span class="ui">Адрес сохранён. Соединение с сервером установлено</span> |
| Соединение не установлено | <span class="ui">Адрес сохранён, но не удалось подключиться к …</span> |
| Сервер ответил кодом ошибки | <span class="ui">Адрес сохранён, но сервер вернул ошибку …</span> |

Во всех трёх случаях адрес уже записан на устройство — проверка на сохранение не влияет.

## Проверка эндпоинтов вручную

Быстрый прогон, чтобы отделить проблему сервера от проблемы телефона:

```bash
# Список за сегодня — самый простой способ проверить, что сервис жив
curl -i https://meter.mosoblenergo.ru/api/today

# Выгрузка снимка на распознавание
curl -i -X POST https://meter.mosoblenergo.ru/api/upload \
  -F "photo=@meter.jpg;type=image/jpeg"

# Создание записи
curl -i -X POST https://meter.mosoblenergo.ru/api/confirm \
  -H "Content-Type: application/json" \
  -d '{"meterNumber":"1234567890","reading":"001234","tariff":"T1","meterType":"Меркурий 230","digitCount":1}'
```

Если `curl` с рабочей станции отвечает, а телефон — нет, ищите причину в мобильной сети: фильтрация трафика оператором, корпоративный VPN, отсутствие доступа к хосту из мобильного сегмента.

> [!TIP]
> Перед выездом на участок с проблемой свяжитесь с обходчиком и попросите открыть шестерёнку и нажать <span class="ui">Сохранить</span>. Ответ на этом экране сразу разделяет три случая: нет сети, неверный адрес, сервер отвечает ошибкой.
