# Как устроено приложение

Раздел для ИТ-службы и поддержки. Описание собрано разбором сборки `MeterParser-v1_0_0.apk`: манифеста, ресурсов и строковой таблицы JS-бандла.

## Состав сборки

| | |
|---|---|
| Идентификатор пакета | `com.meterparser.app` |
| Версия | 1.0.0 (`versionCode 1`) |
| Минимальная версия Android | 7.0, API 24 |
| Целевая версия Android | API 36 |
| Архитектуры | `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64` |
| Размер APK | около 100 МБ |
| Ориентация | Только портретная |
| Тема интерфейса | Только тёмная, цвет заставки `#1A1A2E` |

## Технологии

Приложение написано на **React Native** и собрано через **Expo SDK 57**. JS-код скомпилирован в байт-код движка **Hermes** и лежит в `assets/index.android.bundle` — это единый бандл, отдельных JS-файлов в сборке нет.

Использованные библиотеки, которые видны в сборке:

| Библиотека | Для чего |
|---|---|
| `expo-camera` | Видоискатель, съёмка, управление вспышкой |
| `expo-file-system` | Работа со снимком и его выгрузка |
| `@react-native-async-storage/async-storage` | Хранение адреса сервера на устройстве |
| `@react-navigation` (стековый навигатор) | Переходы между экранами |
| `react-native-screens`, `react-native-gesture-handler`, `react-native-safe-area-context` | Нативная навигация и жесты |

> [!NOTE]
> В сборку попали модели ML Kit для распознавания штрихкодов — их тянет за собой `expo-camera`. Интерфейса сканирования в приложении нет, распознавание целиком серверное. На размер APK эти модели влияют, на работу — нет.

## Экраны

Пять экранов в одном стеке навигации:

| Экран | Назначение |
|---|---|
| `HomeScreen` | Выбор действия, вход в настройки |
| `CameraScreen` | Съёмка табло, управление подсветкой |
| `ReviewScreen` | Сверка распознанных полей, отправка |
| `TodayScreen` | Список записей за день, поиск по номеру |
| `SettingsScreen` | Адрес сервера, проверка связи, сброс |

## Разрешения

| Разрешение | Использование |
|---|---|
| `CAMERA` | Основное. Без него съёмка невозможна |
| `INTERNET`, `ACCESS_NETWORK_STATE` | Обмен с бэкендом |
| `FLASHLIGHT` | Подсветка табло |
| `RECORD_AUDIO` | Объявлено `expo-camera` для видеозаписи. Приложением не используется |
| `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE` | Объявлены библиотеками для работы с файлом снимка |
| `VIBRATE`, `SYSTEM_ALERT_WINDOW` | Служебные, от React Native |

Текст запроса камеры, который видит пользователь: «Приложение использует камеру для фотографирования электросчётчиков».

## Что хранится на устройстве

Единственное, что приложение сохраняет локально, — адрес сервера, в AsyncStorage под ключом:

```
@meter_parser_api_url
```

Ни показаний, ни снимков, ни очереди отправки на устройстве не остаётся. Отсюда два следствия:

- **офлайн-режима нет** — всё, что делает приложение, кроме самой съёмки, требует сети;
- **данные не теряются при смене телефона** — переносить нечего, достаточно установить приложение заново.

Удаление приложения стирает и сохранённый адрес: после переустановки он снова станет заводским.

| Запрос | Когда |
|---|---|

| `POST /api/confirm` | По кнопке <span class="ui">Отправить</span>: подтверждённые поля |
| `GET /api/today` | При открытии экрана <span class="ui">Показания за сегодня</span> |

## Распознавание

Распознавание целиком на сервере. Телефон отправляет снимок и получает готовые значения полей — на устройстве не выполняется ни OCR, ни какая-либо модель.

Практические следствия для поддержки:

- **качество распознавания меняется без обновления приложения** — модель живёт на сервере;
- **отказ распознавания на всех приборах сразу** — признак проблемы на сервере, а не на телефонах;
- **нагрузка на канал заметная** — каждое показание это выгрузка фотографии.

## Развёртывание

Приложение раздаётся файлом APK вне магазинов. Установка требует разрешения «Установка из неизвестных источников» для того приложения, из которого открывается файл.

Обновление ставится поверх без удаления предыдущей версии при условии той же подписи. Смена подписи потребует ручного удаления старой версии на каждом устройстве — это стоит учитывать при пересборке.

При массовой раздаче через MDM разрешение на установку и разрешение камеры выдаются политикой, и первый запуск у обходчика проходит без системных окон.

## На что обратить внимание при развитии

**Нет офлайн-очереди.** Обходчик на объекте без связи не может сдать прибор. Локальная очередь с отложенной отправкой — самое заметное улучшение по эксплуатации.

**Нет идемпотентности отправки.** Если ответ на `/api/confirm` потерялся, обходчик не знает, создалась запись или нет, и проверяет это глазами в списке за день. Ключ идемпотентности в запросе снял бы риск дубликатов.

**Список ограничен сутками.** `GET /api/today` не принимает дату, поэтому вчерашние записи в приложении недоступны.

**Адрес сервера доступен обходчику.** Экран настроек открыт с главного экрана без ограничений. Неверный адрес приводит к потере целой смены, поэтому в корпоративной раздаче адрес стоит фиксировать политикой.
